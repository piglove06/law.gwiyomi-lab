# 예시 모음 (_dataset)

나중에 파인튜닝(LoRA)·프롬프트 개선·평가에 쓸 **좋은 예시 / 나쁜 예시**를 꾸준히 모으는 곳입니다.
법 **내용**을 외우게 하려는 것이 아니라, "주어진 조문을 꼼꼼히 읽고 적용하는 방식"(되묻기·비고 반영·계산·결론 일치)을 가르치기 위한 재료입니다.

## 누가, 어떻게 판정하나
- 판정(👍/👎/보류)은 Claude 가 합니다. 사용자는 법 판단을 하지 않습니다.
- 정답 기준은 **공신력 있는 출처**만: 중앙부처 1차 해석(질의요지·회답), 법제처 법령해석례, 판례, 그리고 **현행 조문 원문 대조**.
- 출처 해석이 오래됐거나(해석일자 없음) 현행 원문으로 확인 못 하면 `보류` — 학습에 쓰지 않습니다.
- 수정 작업·eval 실행 때마다 판단이 분명한 예시를 추가합니다(LOOP_ENGINEERING 수정 작업 규칙 6).

## 파일
- `examples.jsonl` — 한 줄에 예시 하나(JSON).

| 필드 | 내용 |
|---|---|
| id | EX-YYYYMMDD-NN |
| date, system_version, report | 실행 날짜·버전·eval 보고서 경로(_eval 은 저장소에 안 올라감 — 로컬) |
| source | 질문 출처 {type, org, ref} |
| question / clarify / answered | 질문, 되묻기(질문·보기), 되묻기 응답 |
| context_keys | 답변에 들어간 조문 목록(본문은 report 에서 재현) |
| system_answer | 시스템 답변 원문 |
| verdict | 👍 / 👎 / 보류 |
| why | 판정 이유(어디가 맞고 틀렸는지, 원인: 검색·선별·판단) |
| reference_answer, basis, law_checked | 모범 답 요지, 근거 조문, 현행 원문 확인 여부 |
| labeled_by | 판정자 |

## 쓰는 법(나중에)
- 👍 예시: 그대로 "질문+조문 → 답" 학습 쌍.
- 👎 예시: system_answer 대신 reference_answer 로 모범답을 다시 써서 학습 쌍으로(조문 원문으로 재확인 후).
- 보류: 쓰지 않음. 근거가 확인되면 판정을 바꿉니다.
